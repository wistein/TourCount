1. Introduction

TourCount should support you when recording European butterflies.
It allows to register individuals species-specific, separated by sexus and metamorphic stages as well as individually with state and location in the field.
It offers prepared result outputs and substitutes your field book, pencil, and if applicable a camera for documentary pictures.

Databases can be created individually per region and adapted regarding expected butterfly species. The internal database is tour-related, i.e. a new database instance is used for each tour.

The recorded data (metadata, counts and remarks) may either be read on the smartphone for transfer into a butterfly registration system,
e.g. on https://www.falterfunde.de/platform/s4y/falterfunde/index.do
or exported and transferred to a PC for your own processing, where they can be better read or edited.

The app is published on https://github.com/wistein/TourCount with source code and documentation. It is open source, has neither tracking nor advertising functions and does not make use of Google Play Services. It demands only for permits which are needed for its serviceable functions:

- Storage access which is needed for importing species data and DB files, exporting data and the counting results to DB. XLSX or CSV files,
- Location service with GPS the get the location of each count,
- optional internet access for reverse geocoding (get detailed address data) by Nominatim service of OpenStreetMap and
- wakelock to hinder the app from being switched off by the system when inactive, but get dimmed and get an insensitive screen when pocketed or held near the body.


2. Setting up

Before initial use you should adapt the app settings (→ 4. Further Functions).

Then adapt the preliminary species list to the expected species in your region with the species list editing functions (Add, Remove or Edit).

To do this, click "Counting" on the Starting page and then use the “Add Species”, “Remove Species” or “Edit Terms” buttons in the header of the counting page.

All 3 editing pages offer a preselection to ease the selection of a distinguished species. Enter 2 or more letters of the scientific species name and then click the "Search" button to limit the shown list.

On the "Add Species" page select species from the blue scroll-down list of not yet selected species. Changes take effect by the (+)-button in the headline (notice that the selected species disappear from the scroll-down list).
At the end of the scroll-down list, a placeholder for a momentarily indeterminate species (NN) can be adopted and edited later, if necessary after determination.

On the "Remove Species" page select species to remove on the red scroll-down list and tip on the "Delete" button.

On the "Edit Terms" page you may edit the tour name and the terms of each species. (Scientific and local species names, codes generally five digits with leading zeros, as you can see in the following species list table excerpt).

(Part of a species list)
---------------------------------------------------
...
Pieris rapae ..................... 06998
Small white
Pieris napi ....................... 07000
Green-veined white
Pie. napi/rap. compl. ...... 07001*
Small whites compl.
...

The codes will be used as an option to sort the list and as a reference to show corresponding butterfly icons.
The codes derive from the numbering scheme of European butterflies by Karsholt/Razowski, as used e.g. in the German Lepiforum (https://lepiforum.org verwendet).

The *-sign attached to code 07001 in the table above indicates a complex of species that are difficult to distinguish. For sorting purposes, the larger code within the group should be used for such groups.
Caution: A wrong code shows "N/A" or a wrong picture. If necessary, see the "List of Coded Butterflies.pdf" on
https://github.com/wistein/TourCount/tree/master/docs.

Alternatively, a more comprehensive or specialized sample species list can be downloaded from https://github.com/wistein/TourCount/tree/master/docs, copied to the app's data directory "Documents/TourCount" and imported from there, and then customized. (This directory is created when the app is first launched. It is not deleted when TourCount is uninstalled; the data stored there is retained). Changes to species always affect all existing section lists.

Then you should enter general parts of the master data under "Edit Metadata".
Location-related metadata derived from GPS coordinates will be inserted automatically, when reverse geocoding is activated under “Settings”. Some of those could also be manually edited or changed anytime later. Clicking the storage icon saves the data and finishes this function.

When you have created the counting list for all expected species and entered the metadata, the database is ready for export as a loadable "Basic Database" file by the function „Export as Basic DB“ in the menu of the starting page. This saves a copy of the prepared database as an empty "Basic Database" (tourcount0_dl_Tourname.db, where “Tourname” is taken from the metadata, if available) within the app’s data directory "Documents/TourCount".
The app data directory is created during the first app call. When uninstalling TourCount you will not lose your data as this directory remains untouched.

The Basic DB does not contain any count data, comments, or inspection-specific metadata. It just stores the structure of the set-up DB and serves as a template for further tour recordings in the region. It should be renamed suitably, e.g. "tourcount0_en_region xyz.db".
Note: The file name of a Basic DB must always start with the string "tourcount0" ("tourcount" with a trailing "0").

Alternatively you can import and adapt a self-created Basic DB for your tour. Or you may substitute the species list by importing a previously exported species list from TourCount or TransektCount (if installed). Examples for downloading, partly from other European countries than Germany, are provided on
https://github.com/wistein/TourCount/tree/master/docs.

Copy them to the app’s data directory "Documents/TourCount" and import and edit them in TourCount suitably.

The file naming convention for the exported TourCount files:

- Basic DB:       tourcount0_dl_Tourname.db
- Current DB:   tourcount_dl_StartDate_Tourname.db
- Result:           Tour_dl_StartDate_Tourname_os.xlsx
                          (or .csv)
- Species list:  species_dl_Tourname_CurrentDate.csv

with

- blue = fixed string parts,
- dl = data language of local species names
      ("de", "en", "es", "fr", "it"),
- Tourname = tourname
      (filtered for filename conformity),
- StartDate = date and time of the tour start
      (YYYYMMDD-hhmm).
      If not specified the current storage date,
- os = output sorting code ("n" names, "c" codes),
- CurrentDate = current storage date
      (YYYYMMDD-hhmm).


3. Usage

After starting the app, a message about the first GPS fix is displayed and, if applicable, with a message indicating that the detected position is outside the European fauna area (as a reminder that only European species are supported).

Start with "Edit Metadata". Enter the specific metadata of the tour.
You may enter the current date and time by clicking the related field or enter any date and time by long pressing the related field. Finish with the "Save" button.

Continue with "Counting". Select the species by clicking the species line to scroll down the species list.
To count just click the (+)-button of the category (♂|♀, ♂, ♀, Pupa, Larva, Ovo) of the species. The counter will increment and the Individuals page opens. Location info, latitude, longitude, height as well as date and time will be added automatically. Location may be edited and condition rating state 0 - 6 with 0 (undefined), 1 (very good) and 6 (very bad) as well as multiple counts may be applied here.
The “Individual Notes” field lets you select a common individual note from a pop-up list and/or edit the notes.

To accept the shown data go back to the counting page by clicking the "Save" button. Click the (←) button to go back without saving.

The (-)-buttons on the counting page allow for corrections. Mind that the (-)-buttons reduce the individuals list in a last-in-first-out-mode for the corresponding species category.

The “Species Notes” field on the counting page lets you enter notes or select a common species note from a pop-up list with a single click.
If you enter a “0” in this field, the species will also be listet in the results later, despite a count of 0.

Before finishing TourCount after a tour you should complete the metadata with the ending values for time, temperature, wind and clouds. Then use "Export results" to save the current tour results as a .xlsx (MS Excel table) or as a .csv (comma separated values text) table file. The file will be named with data language, tour name, start date and time and saved as "Tour_dl_StartDate_Tourname_os.xlsx" or ".csv in the directory "Documents/TourCount". Without a given start time the current date and time will be used.

To move back one page you generally can use the ⬅-button. To make sure to save changed content you should go back by tipping the respective Add, Delete or Save button.

Finally, the "Counting Results“ page shows your results sorted either by species names or species codes according to the selected Output sort option. Beneath the metadata it shows the totals followed by a list of all counted species with their individual records (time, location, coordinates and species attributes), sorted by the recorded time.
You can enter this page from the Starting page with "Show Results" or the Eye-symbol in the app bar. It may take a second to show up.

To move back one page you can use the "Back" button or arrow in the left upper corner. To make sure to save edited content you should click the Add, Remove or "Save" button if the page has one.

With large amounts of data, the app's response can be somewhat delayed for e.g. import functions or when calling up the results page, as extensive calculations are running in the background. This is indicated by a short message "View gets calculated …".

If the message "TourCount not responding" appears, please reply with "Wait".


4. Further functions

The app menu on the starting page has Settings, Reset, Import, Export, Info and Help functions.

In "Settings" you may adapt the look an feel in some aspects to your wishes, e.g. sorting order of lists and data export, left-/right-hand counting page or sounds and haptic button feedback.

Reverse Geocoding allows for automatic insertion of statements of place (postal code, city, place) into metadata and location data into the individual's record.
For Reverse Geocoding (to produce address info from GPS coordinates) the free service of Nominatim from OpenStreetMap is used (since 2026 limited to 1 request per second and app).
To exclude abuse and for durably reliable queries of address data a valid own email address is necessary.
The mail address will be treated confidentially and will only be used to contact you in case of service problems.
For more info see
https://wiki.openstreetmap.org/wiki/Nominatim.

For preparing a new tour you may use "Reset Data" to reset the tour-specific metadata and all count data.
Alternatively you may import the Basic DB, another tourcount-DB or a species list.

However, after that, the current locality is not recognized again until about 10 seconds later, at which point it is set as the starting locality. Only after the corresponding pop-up message appears can the locality's metadata be automatically inserted on the metadata page. If the metadata page is accessed too quickly, the current location data will be missing. This data would only be added when the metadata page is accessed at a later time.

Android-specifically, TourCount stores the data in an internal SQlite DB in the app's own protected storage area that is not accessible by the user. Therefore, it is necessary to import/export data from/to files in a user accessible storage area.

Starting with app version 3.7.4, DB files are exported with a field for identifying the data language for local species names (German, English, French, Italian, and Spanish). For imported DB files created prior to this update, the correct data language should be selected via “Settings” to ensure proper processing.

With "Import Basic DB" you can select and import an existing Basic DB file that was exported as a template for a regional tour. However, after the import, it takes about 10 seconds for the current locality to be recognized again.
Note: The file name must always begin with the exact character string "tourcount0" (e.g., "tourcount0_en_Kottenforest.db"), otherwise the file cannot be imported as a Basic DB.

When exporting data, the tour name (if it exists in the metadata) will be inserted into the name of the exported file. Here, any characters that violate the filename conventions are removed as necessary.

With "Export Basic DB", the internal DB (without walk-specific data but with general metadata and the current species list) can be exported as the Basic-DB file "tourcount0_dl_Tourname.db" into "Documents/TourCount". This is reasonable if permanent changes have been made to the count list, such as adding new or removing species.

With "Import DB" any appropriately named TourCount DB can be selected and read into TourCount. However, after the import, it takes about 10 seconds for the current locality to be recognized again.
Note: The db file name must always start with “tourcount_” (e.g. tourcount_en_Kottenforest.db), otherwise the file cannot be imported).

"Export Current DB" writes a copy of the DB with all currently contained data as "tourcount_dl_StartDate_tourname.db" into "Documents/TourCount". If exist, the start date and time of the tour get inserted into the filename. Otherwise, the current date gets inserted. If a tour name exists, it is inserted into the filename but eventually gets cleaned up to remove characters that violate file naming conventions.

The function "Import Species List" lets you select and import an available species list. The metadata is retained during import, but all counting data is deleted. If the TransektCount app is installed, the exported species lists can be imported mutually.
Starting with app version 3.7.2, the species list has been updated to include the data language. The available data languages are German, English, French, Italian, and Spanish. When local species names were available, they have been included for the species listed in the app.
There is one drawback when importing a species list created for or with older versions. To work as expected you have to set the correct data language manually in the Settings. However, after the import, it takes about 10 seconds for the current locality to be recognized again.
Note: The file name of a species list must always begin with "species_", otherwise the list cannot be imported.

With "Export Species List" the current species list can be exported as a CSV file (CSV = Comma Separated Values text file) "species_dl_tourname_CurrentDate.csv”. The tour name is also inserted here if it exists in the metadata, and any characters that violate the filename conventions are removed as necessary.
If you imported a species list that was exported from an app version earlier than 3.7.2, you should set its data language in Settings and then re-export the list. After that, the data language will be automatically detected and set in the future.

The functions "Export Results (xlsx)" and "Export Results (csv)" write the counting results with the metadata of the tour into the formatted Excel spreadsheet file “Tour_dl_StartDate_tourname_os.xlsx” or the pre-formatted table textfile ".csv" to "Documents/TourCount". The file names will preferably include the start date of the tour; otherwise, they will include the current date.

The exported table can be sorted in advance (by species or codes) using the result sorting option in TourCount settings, depending on your preference for easier data entry into a central monitoring web page like
https://www.falterfunde.de/platform/s4y/falterfunde/index.do.

The exported result files could be viewed and, to a limited extent, edited in a spreadsheet app such as Collabora (open source, free, based on LibreOffice). It is available in the Collabora Office Store (an additional package source in the F-Droid app store), in the Play Store, or directly at https://www.collaboraoffice.com/downloads/).

The exported .xlsx or .csv result files can also be transferred to a PC for further processing and loaded or imported into a spreadsheet program (tested with MS Excel, LibreOffice Calc and Softmaker PlanMaker).

IT-affine users may also transfer the exported ".db" files to a PC and examine or edit them there with a free tool like "DB Browser for SQLite" (http://sqlitebrowser.org). It lets you edit them manually or per SQL script. Some useful example SQL scripts are published in the docs directory of the GitHub TourCount project site https://github.com/wistein/TourCount/tree/master/docs.


Under "App Info" you find the email address of the author and the history of the app development.

Under "Licenses" you find the license notes for code and figures.

The option menu of the counting page provides a "Photo" function to quickly take a photo and a "Share" function for sending notes using a standard app, like SMS or email.

Optionally, the counter view is temporarily turned off by means of the proximity sensor when the phone is pocketed or closely held to the body. This saves energy, prevents accidental entries and brings the app back immediately when it is used normally again.

The app shows several short pop-up messages in 4 categories:

- Error        (e.g. with a database problem).
- Warning (e.g. in the event of an invalid entry).
- Note         (e.g. if an action might last longer).
- Info          (e.g. after a successful process).
